# 자료실 — 설교 시트지 (`/resources/*`)

설교 시트지를 **찾아서 열어 보고 내려받는 곳**이다. 같은 자료가 예배 영상 화면의 「설교 시트지」 카드로도 나온다 — 한 번 등록한 자료를 두 화면이 같이 쓴다.

| 페이지 | 주소 | 내용 |
|---|---|---|
| 자료 목록 | `/resources/sunday-sermon` · `series-sermon` · `seasonal-sermon` | 「자료 찾기」 검색 · 분류 칩 · 결과 수와 정렬 · 글 중심 목록(A안 «빠른 목록형») |
| 문서 열람 | `/resources/<분류>/<자료id>` | 「자료 목록」 돌아가기 · 제목과 메타 · 내려받기 · 설교 영상 보기 · 열람기(쪽 넘김·확대) |

> 결정 배경: [ADR 0014](../decisions/0014-content-repository-and-video-id-link.md). 시안은 A·B·C 세 안이었고 A안으로 확정(2026-11-13).

## 화면 규칙

**목록**

- 분류 칩: 주일 설교는 **연도**, 시리즈·가정/명절/절기는 **묶음 이름**. 칩은 자료에서 자동으로 나온다.
- 검색: 치는 대로 걸러진다. 제목·묶음·회차(«66회»)·날짜(«2026.10.25»)·본문·원본 파일 이름이 대상이다. **띄어 쓴 낱말이 모두 들어 있으면 맞는다**(순서·사이 글자와 무관 — «성령 9» 로 «성령의 능력, 성령의 열매 9» 를 찾는다). 한 낱말 안의 띄어쓰기·대소문자는 무시한다(«도장깨기» ↔ «도장 깨기»). 숫자로 시작하는 낱말은 앞이 숫자가 아닌 자리에서만 맞는다 — «9» 가 날짜 «02.09» 나 «19회» 에 걸리지 않는다. 숫자만 치면 회차뿐 아니라 본문의 장(«3:36»)도 걸리므로, 회차만 찾으려면 «3회» 처럼 친다.
- 줄(제목)을 누르면 **문서 열람**, 오른쪽 아이콘은 **원본 내려받기** — 별개 동작이다.
- **확장자(PDF·HWP)와 파일 용량은 어디에도 적지 않는다.** 제목·회차·사용 날짜·성경 본문은 적는다. 쪽 수도 적지 않는다 — 시트지가 전부 2쪽이라 정보가 되지 않는다(열람기의 «1 / 2» 로 충분하다).
- 날짜는 문서·제목에서 확인된 것만 쓴다. 모르면 연도만(«2025년»), 그것도 모르면 비운다 — 지어내지 않는다.

**문서 열람**

- 「자료 목록」 링크는 한 번만. 돌아가면 검색어·칩·정렬·스크롤 자리가 그대로이고 눌렀던 줄에 포커스가 돌아온다(`resourceListState`).
- 자료의 실제 형태대로 그린다:

| 형태 | 열람 | 내려받기 |
|---|---|---|
| PDF | 미리보기 쪽 | 원본 파일(올린 이름 그대로) |
| 한글 파일 + 미리보기 있음 | 미리보기 쪽 | 원본 파일 |
| 한글 파일 + 미리보기 없음 | «한글 파일로 제공되는 자료입니다…» 안내 | 원본 파일 |
| 첨부 없이 이미지뿐 | 미리보기 쪽 | 없음 — 보고 있는 쪽의 «이미지 저장» 만 |

- 「설교 영상 보기」: 연결된 영상이 사이트의 예배 페이지에 있으면 **같은 창**에서 그 설교 페이지로 가고 바로 재생된다. 사이트에 없는 영상이면 «유튜브에서 보기»(새 창). 영상이 없는 자료에는 버튼이 없다.
- 없는 id · 다른 분류의 id · 임시저장 자료는 404.

## 구조

```
data/resourcesSeed.ts ──▶ api/resourceRepository ──┬─▶ widgets/ResourceLibrary  → features/ResourceListPage
   (지금: 시드)            list · get · forVideo     ├─▶ widgets/ResourceDocument → features/ResourceViewPage
   (나중: DB)              임시저장은 여기서 거른다   └─▶ worship-video 의 SermonWatch → 「설교 시트지」 카드(api/sheetLinks)
```

| 파일 | 맡은 일 |
|---|---|
| `api/resource.types.ts` | 자료의 모양(`Resource`) — 분류·묶음·회차·날짜·파일·미리보기 쪽·`videoIds`·상태 |
| `api/resourceRepository.ts` | 공개 자료 읽기. **화면은 이 저장소로만 읽는다**(시드 직접 import 금지). 전부 async — DB 로 바뀌어도 부르는 쪽은 그대로 |
| `api/resourceList.ts` | 검색·칩·정렬·표시 문구·내려받기 대상(순수) |
| `api/resourceListState.ts` | 목록의 조건과 돌아올 자리를 화면 밖에 둔다 |
| `api/resourceViewer.ts` | 열람기의 설명 줄·미리보기 없는 자료의 안내(순수) |
| `api/sheetLinks.ts` | 자료 → 예배 화면의 시트지 카드 정보 |
| `api/resourceInput.ts` | 관리자 등록 값의 검증(zod) + 유튜브 주소 → 영상 id |
| `config/resourceSections.ts` | 세 분류 ↔ 주소. 사이트 메뉴와 같아야 한다(테스트가 잠근다) |

분류 칩 줄(`ChipRow`)과 열람기의 쪽 넘김·확대 부품(`ViewerControls`)은 `src/shared/components/features/` 의 것을 예배 영상·교회소식과 같이 쓴다. 확대 단계 계산은 `src/shared/lib/zoomSteps.ts`.

파일은 `public/files/resources/<id>.pdf|hwp`, 미리보기 쪽은 `public/files/resources/pages/<id>-<n>.webp`.

## 관리자 등록과 예배 시트지 연결

**지금 있는 것**: 자료 모양, 공개 읽기 저장소, 등록 값 검증, 두 화면의 연결. **아직 없는 것**: 관리자 로그인·등록 화면·DB·파일 업로드([ADR 0008](../decisions/0008-admin-backend-vercel-supabase.md)의 `/admin` + Supabase — 계정·프로젝트가 아직 없다).

등록 흐름(관리자가 생기면):

1. 제목·분류·묶음·사용 날짜를 적고 파일(또는 이미지)을 올린다.
2. 연결할 설교가 있으면 영상을 찾아 고른다 — 유튜브 주소를 붙여 넣어도 **영상 id** 로 바뀐다(`parseYoutubeVideoId`). 재생목록 주소·제목은 받지 않는다.
3. 임시저장 또는 공개. 공개하면 자료실과 그 영상의 「설교 시트지」 카드에 함께 나온다.

연결 규칙:

- 기준은 **유튜브 영상 id** 하나다. 재생목록·파일 이름·제목으로 짐작하지 않는다.
- 다대다 — 한 영상에 자료 여러 개(카드가 여러 개 나온다), 한 자료에 영상 여러 개(버튼이 여러 개 나온다).
- 영상이 없는 자료(가정·명절)는 `videoIds` 가 빈 배열이다.
- 임시저장은 저장소가 걸러 어느 공개 화면에도 나가지 않는다. 수정·교체·삭제는 자료 한 곳만 바꾸면 두 화면에 같이 반영된다.

연동할 때 할 일:

| 무엇 | 내용 |
|---|---|
| DB | `resources`(자료) + `resource_videos`(자료 id · 영상 id, 다대다). `status` 로 공개 여부. 행 수준 권한: 공개 화면은 `published` 만 읽는다 |
| 파일 | Supabase Storage. 원본과 미리보기 쪽 주소를 DB 에 적는다(`file.url` · `pages[].src`) |
| 미리보기 | PDF 를 올릴 때 쪽 그림(WebP, 긴 변 1700px 안팎)을 만든다. 한글 파일은 미리보기를 따로 올리거나 없이 둔다 |
| 저장소 | `resourceRepository` 의 `load` 를 DB 조회로 바꾼다. 화면 코드는 그대로 |
| 갱신 | 등록·수정 뒤 `revalidateTag` 로 자료실과 그 영상 페이지를 다시 만든다(지금 열람 페이지는 10분 주기) |
| 영상 고르기 | 등록 화면의 영상 검색은 예배 페이지 목록(`fetchSermonLibrary`)을 쓴다 — 유튜브를 더 부르지 않는다 |
| 이전 | 시드 57건을 DB 로 옮긴다. id(«게시판-글번호»)는 그대로 두면 주소가 유지된다 |

## 미결·다음

- 파일 82MB 가 `public/files` 에 있다(자료실 42MB · 주보 40MB · 앨범 0.4MB). Storage 가 없어 저장소에 둔다 — Storage 가 생기면 옮기고 주소만 바꾼다. 주보가 매주 4장(약 0.45MB)씩 는다.
- 기존 사이트의 날짜가 이상한 자료가 있다(「우리를 살리는 소그룹 2」가 1편보다 1년 뒤). 원본대로 두었다 — 교회에 확인이 필요하다.
