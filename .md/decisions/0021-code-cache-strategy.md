# ADR 0021: 공통코드 · 분류는 서버 데이터 캐시(하루) + 고칠 때 태그로 바로 지우기

**상태**: 대체됨 (→ ADR 0023)
**날짜**: 2026-11-20

## 배경

공통코드 · 분류는 드롭다운 · 조건 · 표의 이름으로 거의 모든 화면이 읽지만 바뀌는 일은 드물다. 사용자 요청(2026-11-20): 처음 한 번 읽어 전역으로 쓰고, 캐시 만료는 하루, 코드를 더하거나 고치면 갱신. Vercel 에 배포한다.

## Next.js 16 + Vercel 의 캐시 층(이 프로젝트 기준)

이 프로젝트는 Cache Components(`cacheComponents`, `'use cache'`)를 켜지 않았다 — 공개 사이트가 페이지 단위 `export const revalidate`(ISR)를 쓰는 «이전 모델» 이다. 켜면 앱 전체의 그리기 방식이 바뀌므로 따로 옮긴다.

| 층 | 어디 | 무엇이 들어가나 | 얼마나 | 이 결정에서 |
|---|---|---|---|---|
| ① 요청 안 중복 제거 | 서버, 요청 하나 | `React.cache()` 로 감싼 함수 결과 | 그 요청이 끝날 때까지 | `loadAdminContext` 가 쓴다 |
| ② 서버 데이터 캐시 | 서버(Vercel: 모든 리전이 함께 쓰는 저장소) | `unstable_cache` · `fetch(..., { next })` 결과 | 정한 시간 / 태그로 지울 때까지, **배포가 바뀌어도 남는다** | **공통코드 · 분류(하루, 태그 `codes` · `categories`)** |
| ③ 페이지 캐시(ISR) | 서버 + Vercel CDN | 공개 페이지의 HTML · RSC | 페이지의 `revalidate`(60~600초) | 공개 사이트(그대로) |
| ④ 브라우저 라우터 캐시 | 브라우저 | 지나온 화면의 RSC | 동적 화면은 0초(이동하면 서버에 다시 묻는다) | 관리자 화면은 매번 서버에 묻는다 |

- **RSC 와 CSR**: 코드는 서버 컴포넌트가 ② 에서 읽어 화면을 그리고, 드롭다운 같은 클라이언트 컴포넌트에는 **선택지를 props 로 넘긴다.** 브라우저가 코드를 따로 부르지 않는다(브라우저 쪽 캐시 · 요청이 없다).
- **관리자 화면은 동적**(로그인 쿠키를 읽는다) — 화면은 매번 서버에서 그리지만, 그 안의 코드 읽기는 ② 에서 꺼내 DB 에 가지 않는다.

## 결정

1. `src/shared/api/codeCache.server.ts` — `getCodeBook()` · `getCategoryBook()`. `unstable_cache` 로 감싸 **하루(86400초)** 두고, 태그 `codes` · `categories` 를 단다.
   - 하루가 지나면 다음 요청은 옛 값을 바로 받고, 뒤에서 새로 읽는다(stale-while-revalidate).
   - 쿠키 없는 읽기 전용 연결(`readClient.server.ts`, 공개 키)로 읽는다 — 캐시 안에서는 요청(쿠키)을 볼 수 없고, 두 표는 누구나 읽는다.
   - DB 오류는 던진다 — 빈 목록이 하루 동안 캐시되지 않게.
   - 캐시 열쇠에 배포 id(`VERCEL_DEPLOYMENT_ID`)를 넣는다 — ② 는 배포가 바뀌어도 남으므로, 변경 파일(reference.sql)로 코드가 늘어도 새 배포가 새로 읽게.
2. 화면 도우미(`src/shared/api/codeBook.ts`): `codeOptions`(켜진 코드만, 수정 화면은 고른 값 유지) · `codeLabel`(값 → 이름) · `categoryOptions`(값 = 분류 id).
3. **고칠 때 바로 지운다**: 코드 · 분류를 더하기 · 이름 · 사용 여부 · 순서를 바꾸는 Server Action 이 `updateTag('codes' | 'categories')` 를 부른다. `updateTag` 는 Server Action 전용으로, 다음 요청이 옛 값 대신 **새 값을 기다려** 읽는다(고친 사람이 바로 본다). Vercel 에서는 이 지우기가 모든 리전에 퍼진다.
4. **고치는 화면(코드 관리 · 분류 관리)은 캐시를 쓰지 않는다** — 고친 값을 바로 보고, 동시 수정 검사(updated_at)가 정확해야 한다.
5. DB 에서 직접(SQL) 코드를 고쳤을 때는 최대 하루 늦다. 바로 반영하려면 Vercel 대시보드 › 프로젝트 › Settings › Caches 에서 Data Cache 를 비우거나, 다시 배포한다.

## 대안

- **Cache Components(`'use cache'` + `cacheTag` + `cacheLife('days')`)**: Next 16 이 권하는 방식이고 `unstable_cache` 를 대신한다. 다만 켜는 순간 공개 사이트의 `revalidate` 설정 · 그리기 방식을 함께 옮겨야 한다. 옮길 때 이 파일 하나만 바꾸면 되게 캐시를 한 곳에 모았다.
- **브라우저에서 한 번 받아 전역 상태(store)에 두기**: 화면이 대부분 서버 컴포넌트라 이득이 없고, 탭마다 다시 받으며, 고친 뒤 다른 사람의 브라우저를 지울 방법이 없다.
- **요청마다 DB 읽기**: 작은 표라 느리지는 않지만, 공개 화면 조건 · 드롭다운이 늘면 요청마다 DB 를 부른다.
