# ADR 0013: 자료·소식은 저장소 계층으로 읽고, 자료와 설교 영상은 유튜브 영상 id 로 잇는다

**상태**: 채택
**날짜**: 2026-11-16

## 배경

자료실(설교 시트지)과 교회소식(주일광고·주보·성복의 뜰·교회앨범)의 화면을 시안에서 확정했다(자료실 A · 주보 B · 앨범 C, 주일광고·성복의 뜰은 예배와 같은 영상 화면). 내용은 나중에 관리자에서 등록할 계획인데([ADR 0008](0008-admin-backend-vercel-supabase.md)), 관리자·DB·Storage 는 아직 없다(계정도 없다).

두 가지를 정해야 했다.

1. 관리자가 없는 지금 화면을 무엇으로 채우고, 나중에 DB 로 바꿀 때 무엇을 고치게 할 것인가.
2. 설교 시트지를 자료실과 예배 영상 화면 양쪽에 보이려면 자료와 영상을 무엇으로 이을 것인가.

## 결정

**공개 화면은 저장소 계층(`resourceRepository` · `newsRepository`)으로만 읽는다. 지금은 기존 사이트에서 옮긴 시드를 읽고, 관리자·DB 가 생기면 저장소의 `load` 만 바꾼다. 자료와 설교 영상은 유튜브 영상 id 로만 잇고(다대다), 그 연결은 자료 쪽에 한 번만 적는다.**

- 저장소 함수는 지금도 async 다 — DB 조회로 바뀌어도 부르는 쪽이 그대로다.
- 임시저장(`status: 'draft'`)과 보여 줄 것이 없는 글(영상 id·그림이 빈 글)은 저장소가 거른다. 화면마다 따로 거르지 않는다.
- 자료(`Resource`)에 `videoIds` 를 둔다. 예배 영상 화면은 `resourceRepository.forVideo(영상id)` 로 그 영상의 자료를 찾아 「설교 시트지」 카드를 그리고, 자료실의 「설교 영상 보기」는 영상 id 가 사이트의 어느 예배 페이지에 있는지 찾아(`sermonLinkFor`) 그리로 보낸다.
- 주일광고·성복의 뜰은 예배 설교의 영상 화면을 그대로 쓴다. 영상의 출처만 다르다 — 예배는 유튜브 재생목록, 교회소식은 등록한 게시글(게시글 하나 = 영상 id 하나).
- 파일은 Storage 가 생기기 전까지 `public/files` 에 둔다.

## 대안 비교

**자료와 영상을 잇는 기준**

| 안 | 결과 |
|---|---|
| 제목·파일 이름으로 맞추기(«사도행전 강해 66») | **탈락** — 표기가 조금만 달라도 끊기고, 같은 제목이 둘이면 잘못 이어진다. 기존 자료에 파일 이름과 제목이 다른 것이 있다 |
| 재생목록 단위로 잇기 | **탈락** — 시트지는 설교 한 편의 것이다. 재생목록에 넣고 빼는 것만으로 연결이 바뀐다 |
| 영상 쪽에 자료 주소를 적기(유튜브 설명란 등) | **탈락** — 유튜브와 사이트 두 곳을 고쳐야 하고, 임시저장·삭제를 반영할 수 없다 |
| **유튜브 영상 id, 자료 쪽에 적기** | **채택** — 영상 id 는 바뀌지 않는다. 자료 하나만 고치면 두 화면에 반영된다 |

**관리자가 없는 동안의 자료**

| 안 | 결과 |
|---|---|
| 화면이 시드 파일을 직접 import | **탈락** — DB 로 바꿀 때 화면을 전부 고쳐야 하고, 임시저장 거르기가 화면마다 흩어진다 |
| 지금 Supabase 를 붙이기 | **탈락** — 교회 명의 계정·프로젝트가 없다. 임의로 만들지 않는다 |
| 가짜 관리자 화면(저장되지 않는 등록 폼) | **탈락** — 동작하지 않는 화면을 만들지 않는다. 등록 값 검증(`resourceInputSchema`)과 영상 id 변환만 먼저 둔다 |
| **저장소 계층 + 시드** | **채택** |

**주일광고·성복의 뜰의 영상 출처**

| 안 | 결과 |
|---|---|
| 유튜브 재생목록(예배와 같은 방식) | **보류** — 올리기만 하면 되는 장점이 있지만, 기존 게시글이 재생목록이 아니라 글마다 영상을 붙인 것이고 성복의 뜰은 분류(부흥집회·교회소식)를 사람이 정한다. 주일광고 재생목록이 따로 있으면 그때 바꾼다 |
| **등록한 게시글(영상 id)** | **채택** |

## 결과 / 영향

- 영상 화면 도메인(`worship-video`)이 교회소식 영상도 그린다. 페이지 설정이 재생목록 페이지(`WORSHIP_PAGES`)와 등록 영상 페이지로 나뉘고, 페이지마다 다른 문구·묶는 방식은 `videoPageProfile` 에 있다.
- 도메인끼리 서로 가져다 쓴다 — `worship-video` → `resources`(시트지 카드) · `news`(영상 게시글), `resources` → `worship-video`(영상 주소 찾기 · 눌러서 넘어갈 때의 재생 요청 `playIntent`). 넘나드는 것은 저장소·순수 함수·재생 요청 표시까지이고, 화면 부품은 도메인을 넘지 않는다 — 세 도메인이 같이 쓰는 모양은 `src/shared/` 에 둔다(`ui/controlStyles` · `features/ChipRow` · `features/ViewerControls` · `lib/zoomSteps`).
- 자료실 열람 페이지가 유튜브 응답(1시간 캐시)에 기댄다 — 그래서 빌드 때 만들지 않고 처음 열릴 때 만든다. 목록을 못 받으면 없다고 단정하지 않고 사이트 안 주소를 준다.
- 파일 82MB(자료실 42MB · 주보 90호 40MB)가 저장소(공개 레포)에 들어간다. Storage 로 옮기면 `public/files` 를 지우고 주소만 바꾼다.
- 관리자 착수 때 할 일은 [resources.md](../domains/resources.md) «연동할 때 할 일» 에 있다. DB 표·권한·업로드·미리보기 만들기·갱신 신호가 그 범위다.
- 영상 id 가 사이트 페이지에 없으면(재생목록에서 빠짐) 자료실의 버튼은 유튜브로 가고, 예배 화면의 카드는 그 영상 페이지가 없으니 나올 곳이 없다 — 자료는 자료실에 그대로 남는다.
