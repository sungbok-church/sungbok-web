# ADR 0025: 관리자 순서 바꾸기는 끌어서 놓기(dnd-kit) + DB 함수 한 번으로 저장

**상태**: 채택
**날짜**: 2026-11-23

## 배경

메뉴 관리 · 분류 관리 · 코드 관리는 줄마다 ↑/↓ 버튼으로 한 칸씩 옮겼다. 누를 때마다 저장 + 토스트가 한 번씩 나가 다섯 칸을 옮기면 저장이 다섯 번이었고, 저장 한 번도 바뀐 줄을 하나씩 고치는 방식(`applyMove`)이라 중간에 실패하면 순서가 반쯤 바뀐 채 남았다. 표는 폭 640px 이 있어야 해 휴대폰에서는 옆으로 밀어야 했다. [ADR 0012](0012-date-temporal-and-admin-libraries.md) 는 «끌어서 순서 바꾸기처럼 CSS 로 어려운 요구가 생기면 다시 본다» 고 남겨 두었다.

## 결정

**끌어서 놓기는 `@dnd-kit/core` 6.3.1 + `@dnd-kit/sortable` 10.0.0 + `@dnd-kit/utilities` 3.2.2(정확한 판 고정)로 하고, 놓은 순서는 DB 함수 `public.reorder_rows(p_table, p_ids)` 한 번으로 저장한다.**

- 손잡이(GripVertical 버튼)만 끈다. 포인터는 4px 넘게 움직여야 끌기(손가락으로 이름 칸 · 스위치를 누르는 것과 겹치지 않게), 키보드는 `KeyboardSensor` + `sortableKeyboardCoordinates`, 화면 낭독기 문장은 한글. 위아래로만 움직인다(작은 modifier 하나 — `@dnd-kit/modifiers` 는 넣지 않음). SSR 어긋남을 막으려고 `DndContext` 에 `useId()` 를 준다.
- 놓으면 `useOptimistic` 으로 바로 그 순서를 보이고 Server Action 한 번. 실패하면 서버의 순서로 돌아가고 `router.refresh()`.
- `reorder_rows` 는 security invoker(행 권한 · guard · stamp · audit 트리거가 로그인한 사람으로 그대로). 표는 메뉴 · 분류 · 코드만, 받은 id 목록이 한 무리(메뉴: 같은 영역 + 같은 상위, 분류 · 코드: 같은 group_key)의 전부와 정확히 같아야 한다 — 빠짐 · 더함 · 겹침 · 다른 무리 섞임은 아무것도 바꾸지 않고 오류(23514, 한글 문장). 무리의 줄을 id 순으로 `FOR UPDATE` 잠가 동시에 옮기면 차례로 돈다. 순서 값은 10, 20, 30 …, 값이 바뀐 줄만 고친다.

## 대안 비교

| 대안                                | 판단                                                                                                                                                |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `@dnd-kit/react` 0.5.x(새 API)      | 탈락(지금은). React 19 를 정식 지원하지만 1.0 전이고 2026-10-31 판이 최신이라 바뀔 여지가 크다. 1.0 이 나오면 옮기기를 다시 본다                    |
| `motion` 의 `Reorder`               | 탈락. 키보드로 옮기기 · 화면 낭독기 알림이 없어 직접 만들어야 한다                                                                                  |
| 브라우저 기본 HTML5 끌어서 놓기     | 탈락. 터치에서 동작하지 않고 키보드 · 낭독기 지원이 없다                                                                                            |
| ↑/↓ 유지 + 저장만 묶기              | 탈락. 여러 칸 옮기기가 여전히 클릭 여러 번이다                                                                                                      |
| 줄마다 update 를 여러 번(지금 방식) | 탈락. 한 트랜잭션이 아니라 중간 실패 시 순서가 반쯤 바뀐다. 표 이름을 받는 DB 함수 하나(분기마다 고정 SQL, 동적 SQL 없음)로 세 화면을 함께 처리한다 |

## 결과 / 영향

- `moveMenu` · `moveCode` · `moveCategory` · `applyMove` · `moveItem`(reorder.ts) · `moveSchema` 를 지우고 `reorderMenus` · `reorderCodes` · `reorderCategories`(`{ ids }`, `reorderSchema`) · `applyReorder` 로 바꿨다. 줄 옮기기 계산은 공용 `@/shared/lib/reorder`.
- 표 칸: 손잡이 · 이름 · (넓은 화면만) 둘째 칸 · 사용. 640px 최소 폭을 없앴다 — 390px 에서는 둘째 칸 값이 이름 밑에 작게 나온다.
- 다른 사람이 그사이 줄을 더하면 저장이 거절된다(«목록이 그사이 바뀌었습니다. 새로고침한 뒤 다시 옮겨 주세요»). 이름 · 사용 여부의 동시 수정 검사(updated_at)와 달리 순서는 «무리가 같은가» 만 본다 — 같은 무리를 두 사람이 거의 동시에 옮기면 뒤에 저장한 순서가 남는다.
- 순서를 저장하면 그 줄들의 `updated_at` 이 바뀐다. 다른 탭에 열어 둔 같은 줄의 이름을 고치면 «다른 사람이 먼저 고쳤습니다» 가 난다(전과 같음).
- 운영 DB 적용은 변경 파일 `20261123090549_reorder_rows.sql` 을 사용자 승인 뒤에.
