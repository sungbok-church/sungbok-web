# 영상은 유튜브 기준 — 재생목록 → DB 동기화 (묶음 E) 계획

> 사용자 결정(2026-11-25): 영상은 **유튜브만 관리**한다. 관리자에서 영상을 등록 · 고치는 화면은 두지 않는다(관리 지점이 둘이 되므로). 사이트는 유튜브 재생목록을 DB 에 받아 두고 DB 만 읽어 «유튜브에 있는 그대로» 보인다. 짧은 계획 → 바로 구현.

**Goal:** 예배 설교 · 주일광고 · 성복의 뜰 영상이 모두 «유튜브 재생목록에 넣으면 사이트에 나온다» 한 방식으로. 공개 화면은 유튜브를 직접 부르지 않고(라이브만 예외) DB 를 읽어, 쿼터 · 유튜브 장애가 화면에 닿지 않는다.

**Architecture:**

```
유튜브 재생목록 ──동기화(재생목록 전체, 10분에 한 번까지)──▶ DB youtube_videos(페이지 · 영상 id · 순서 · 제목 · 설명 · 날짜 · 썸네일)
   언제: ① 영상 페이지의 서버 캐시가 다시 그려질 때(방문이 있을 때, 10분 간격 — 방문자는 기다리지 않는다)
         ② 하루 한 번 예약 작업(/api/cron/daily — 방문이 없는 날도)
   여러 곳이 동시에 불러도 한 번만(claim_youtube_sync), 바꾸기는 한 트랜잭션(replace_youtube_videos — 재생목록에서 빠진 영상은 지운다)
공개 화면 ──▶ DB 의 줄을 읽어 제목 · 설명을 지금처럼 읽는다(sermonParse) → 설교 목록 · 한 편 · 자료실 «설교 영상 보기»
```

- **DB 에는 유튜브 값만** 담는다(제목 · 설명 원문). 시리즈 · 회차 · 본문 · 설교자 · 설교일은 읽을 때 뽑는다 — 읽는 규칙을 고치면 다시 받지 않아도 바로 반영된다.
- **유튜브를 못 읽으면** DB 의 마지막 내용을 그대로 보인다(동기화 실패는 로그만). DB 를 못 읽으면 지금처럼 직전 페이지 유지(loadForPage).
- **라이브**(홈의 라이브 무대)는 분 단위라 지금처럼 유튜브에 직접 묻는다(브라우저 60초 · 서버 60초 · CDN 30초).
- 쓰기는 서버 전용 키로만 — 방문자 · 관리자에게 쓰기 권한을 주지 않는다. 만능 키를 쓰는 곳에 동기화 파일 하나를 더한다(lint 예외).

**Spec:** 예배 영상 규칙은 [domains/worship-video.md](../domains/worship-video.md), 교회소식 영상은 [domains/news.md](../domains/news.md), 캐시는 [ADR 0024](../decisions/0024-cache-components.md).

## 단계

| 단계 | 내용 |
|---|---|
| **E1 설교** (지금) | 표 · 동기화 · 예약 작업 연결 → 예배 › 주일예배(«주일 예배 설교» 재생목록)가 DB 를 읽는다. 새 설교가 보이기까지 1시간 10분 → 10분 남짓 |
| E2 주일광고 · 성복의 뜰 | **교회가 유튜브에 두 재생목록을 만든 뒤**(일부 공개 영상도 재생목록에 넣으면 받을 수 있다 — 채널의 일부 공개 영상 목록은 키로 받을 수 없다). 재생목록 주소를 설정에 넣으면 동기화가 시작된다. 홈 «광고 영상» 도 임시(«예배 찬양») 대신 광고 재생목록으로. 그다음 관리자 «주일광고 · 성복의 뜰» 메뉴 · 그 분류 · 첫 화면 카드 · `news_videos` 를 지운다. 예전 117편 중 재생목록에 없는 109편(2026-11-25 확인 — 모두 채널의 일부 공개 영상)은 재생목록에 넣으면 그대로 이어지고, 안 넣으면 그때 정한다 |

## E1 과제

- [x] **T1 DB** — `youtube_videos`(page · video_id · position · title · description · published_at · added_at · thumbnail · poster · synced_at, 기본 키 (page, video_id)) — 누구나 읽기, 쓰기는 서버 전용 키. `youtube_sync`(page · synced_at · claimed_at) + `claim_youtube_sync(page, every)`(10분 안에 했거나 다른 곳이 하는 중이면 false) · `replace_youtube_videos(page, rows)`(한 트랜잭션). pgTAP.
- [x] **T2 동기화** — `youtubeSync.server.ts`: 재생목록 전체를 받아(50개씩, Data Cache 없이) 줄로 바꾸고(지금의 수집 규칙 그대로 — 썸네일 없는 삭제 · 비공개 영상 빼기, 같은 영상 한 번) 넣는다. 받다가 실패하면 넣지 않는다(반쪽 목록으로 지우지 않게). 테스트 먼저.
- [x] **T3 읽기** — `worshipVideo.server` 의 예배 페이지 수집을 «동기화할 때가 됐으면 동기화 → DB 읽기» 로. 줄 → 설교(`Sermon`)는 순수 함수(지금 규칙 그대로). 바깥 모양(`fetchSermonLibrary` · `fetchSermonDescription`)은 그대로라 화면 · 자료실 · /api 는 바뀌지 않는다.
- [x] **T4 예약 작업** — `/api/cron/daily` 가 정리 뒤 모든 재생목록 페이지를 동기화(10분 간격과 상관없이).
- [ ] **T5 운영** — DB 변경 적용(사용자 승인, 코드보다 먼저 — 새 코드가 새 표를 읽는다) → 배포 → 빌드는 받지 않으므로 배포 직후 설교 목록을 한 번 열어 첫 받기를 일으킨다(또는 예약 작업) → 주일예배 199편 안팎이 들어왔는지 확인. 문서(worship-video.md 의 «반영 시점» · 구조 그림, ADR 0024 보충).
