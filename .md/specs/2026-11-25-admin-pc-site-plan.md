# 관리자 패키지 C(사이트 화면 + 새가족) 구현 계획

> 사용자 결정: 짧은 계획 → 바로 구현. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 교회 사람이 다음세대 부서(소개 · 담당자 · 사진) · 홈 히어로(사진 · 유튜브) 를 관리자에서 고치면 공개 사이트에 바로 보이고, 홈의 «새가족 등록 · 문의» 가 실제로 접수되어 관리자 접수함에 쌓인다(담당자 알림 메일 · 엑셀 · 1년 보관).

**Architecture:** DB(`departments` · `department_staff` · `home_hero` · `newcomers` · `submission_attempts`, 부서 범위 함수, 파일 묶음 주인 뷰)는 `schema.sql` 에 이미 있다 — 구조를 바꿔야 하면 정본을 고치고 `db:sync`. 파일 올리기는 패키지 B 의 통로(`FileListField` · `writeFileList`)를 그대로 쓰고, 부서 사진 · 히어로 사진만 **폭별 파일**(`files.variants`)을 함께 만든다. 공개 화면은 저장소 계층(`load`)만 DB 로 바꾸고, 사진 부품이 올린 사진(주소 · 크기 · 폭별 파일)을 받게 넓힌다.

**Tech Stack:** 패키지 B 와 같음 + 엑셀 `exceljs`(서버에서만) + 메일 Resend(C3, 준비되면)

**Spec:** [2026-11-17-admin-design.md](2026-11-17-admin-design.md) — 6.4(부서 범위) · 6.8 · 6.9 · 6.11 · 6.12 · 6.13 · 7 · 9(C) · 12(메일). 지금 있는 틀은 [domains/admin.md](../domains/admin.md), 앞 패키지는 [-pb-content-plan.md](2026-11-24-admin-pb-content-plan.md).

## 단계

한 단계가 끝날 때마다 리뷰 → 전체 검증 → 커밋 · 푸시 · 운영 배포. 자료 옮기기(운영 DB · Storage 쓰기)와 운영 DB 변경은 **사용자 승인 뒤**에 한다.

| 단계 | 내용 |
|---|---|
| **C1 다음세대 부서** | 부서 고르기 → 소개 · 담당자 · 사진 세 구역(한 화면). 부서 범위(담당 부서만). 사진은 폭별 파일. 공개 부서 페이지 8개를 DB 로, 사진 부품이 올린 사진을 받게. 지금 값(글 · 담당자 9명 · 사진 부서마다 12장) 옮기기 → 코드의 값 · 부서 전용 사진 지우기 |
| C2 홈 히어로 | 유튜브가 히어로 · 변형 연출과 어떻게 이어지는지 **시안**(사용자가 고름) → 설정 화면(종류 · 대표 사진 · 유튜브 주소 · 미리보기) → 공개 히어로를 DB 로(장애 대비 사진 한 장은 레포에) → 지금 사진 옮기기 |
| C3 새가족 | 공개 패널의 보내기를 Server Action 에(검증 · 동의 · 허니팟 · 횟수 제한 · 서버 전용 키로 넣기) → 접수함(목록 · 상세 · 상태 · 메모 · 담당자 · 완전 삭제) · 엑셀 · 첫 화면 «처리 안 된 새가족» · 메뉴 배지 → 알림 메일(메일 서비스가 준비되면) |

## Global Constraints

- 패키지 A · B 의 제약을 그대로 따른다(shadcn 규칙 · 화면 표준 · 글자 최소 · 공개 화면 장애 대비 · 공개 화면에 Supabase 클라이언트를 싣지 않음 · 로직 모듈은 테스트 먼저).
- 부서 · 히어로는 **글이 아니라 설정**이다 — 휴지통 · 복제 · 공개/임시저장이 없다. 저장하면 바로 공개된다(설계 6.10 의 «사이트 화면»). 수정 아래 막대 = [취소] · [미리보기] · [저장].
- 부서 범위: 담당 부서가 있는 사용자는 자기 부서만 고르고 고친다(DB `can_edit_department` 가 다시 막는다).
- 새가족은 **개인정보**다 — 방문자에게 DB 권한을 열지 않는다(서버 전용 키로 넣기), 알림 메일에 개인정보를 싣지 않는다, 이력에는 값 대신 «바뀜» 만, 화면 밖으로 나가는 것은 엑셀뿐이고 그 기록(EXPORT)을 남긴다.

## 내가 정한 값(계획에서 확인)

- **폭별 파일**: 부서 사진 · 히어로 사진은 올릴 때 브라우저가 가로 640 · 960 · 1280 · 1920px(줄인 그림보다 좁은 것만) WebP 를 함께 만들어 올리고 `files.variants` 에 적는다. 화면은 지금 있는 `pickVariant` 로 고른다. 옮기기 스크립트는 같은 폭을 `sharp` 로 만든다.
- **담당자 직함**: 지금 글자 → 공통코드 `STAFF_ROLE`(간사 → COORDINATOR, 전도사 → EVANGELIST, 목사 → PASTOR).
- **부서 «맨 아래 한 줄»**: 지금 8개 모두 자리표시 문구(«처음 오는 가정을 위한 안내 한 줄…») + 고정 문구 «부서에서 취합한 뒤 이 자리에 적습니다» 다. 옮길 때 **비워 두고, 비어 있으면 그 줄을 그리지 않는다** — 부서가 직접 적는다.
- **샘플 사진**: 지금처럼 부서마다 12장을 그대로 옮긴다(설계 6.13 «샘플 포함»). 여러 부서가 같이 쓰는 사진은 Storage 에 한 번만 올리고 부서마다 `files` 줄을 둔다. 홈이 같이 쓰는 사진(`dep01~09` · `worship` · `main01` · `first-visit`)은 레포에서 지우지 않는다.
- **새가족 횟수 제한**: 같은 접속(IP 해시)에서 10분에 3건 · 하루 10건. 넘으면 «잠시 뒤에 다시 보내 주세요».
- **동의 문구 판**: `2026-11`. 문구에 «접수한 날부터 1년 보관 뒤 지움» 을 적는다.
- **엑셀**: `.xlsx`, 서버에서 만든다(`exceljs` — 방문자 번들에 싣지 않는다). 지금 목록의 조건 그대로 내려받고, 내려받은 기록(건수)을 이력에 남긴다.

## 사용자 결정(2026-11-25)

1. **메일** — DNS 로그인이 아직 없다. C3 는 접수 · 접수함 · 엑셀까지 만들고, 알림은 «메일 키가 있으면 보낸다» 로 꺼 둔 채 배포한다.
2. **순서** — C1 부서 → C3 새가족 → C2 히어로(시안을 고를 시간을 번다).

## C1 과제

- [x] **T1 올린 사진 받기** — 공개 사진 부품(`Photo`)이 레포 사진(`StaticImageData`)과 올린 사진(`{ src, width, height, variants }`)을 둘 다 받는다. 부서 화면 타입(`Photo.src` · `Staff.photo`)을 올린 사진으로.
- [x] **T2 폭별 파일** — 올리기 칸에 `variants` 선택을 더한다: 그림을 줄인 뒤 가로 640 · 960 · 1280 · 1920px(줄인 그림보다 좁은 것만 — 화면이 가로 폭으로 고른다)를 더 만들어 같은 묶음에 올리고, 파일 항목에 `[[폭, 경로], …]` 로 담는다. 서버가 `files.variants` 에 적는다(경로 규칙 검사 포함). 사진마다 **대체 텍스트** 칸(`withAlt`).
- [x] **T3 한 번에 저장(DB)** — `public.save_department(slug, updated_at, ages, tagline, intro, extra, photos_list_id, staff jsonb)`: 부서 칸 · 사진 묶음 · 담당자(넣기 · 고치기 · 빼기 · 순서)를 한 트랜잭션으로, 화면을 연 뒤 바뀌었으면 null. 로그인한 사람의 권한으로 돈다(부서 범위는 RLS 가 막는다). pgTAP.
- [x] **T4 서버** — 부서 읽기(담당자 · 사진 묶음 · 직함 코드), 입력 스키마(사진 1장 이상 · 30장까지 · 담당자 10명까지 · 사진은 그림만), Server Action `saveDepartment`(담당자 사진은 저장마다 새 묶음), 공개 태그 `departments`.
- [x] **T5 관리자 화면** — `/admin/departments`(고칠 수 있는 부서 목록 — 담당 부서가 있으면 그 부서로 바로) · `/admin/departments/[slug]`(소개 · 담당자 · 사진 세 구역, 미리보기 = 공개 부서 페이지, 변경 이력). `ADMIN_SCREENS_READY` 에 넣는다.
- [x] **T6 공개 화면** — `departmentsLoad.server`(캐시 · 태그 · 장애 대비) → 부서 페이지 8개가 DB 를 읽는다. «맨 아래 한 줄» 이 비면 그리지 않고, 고정 문구 «부서에서 취합한 뒤…» 를 지운다.
- [x] **T7 옮기기** — `scripts/import-departments.mjs`(여러 번 돌려도 같은 결과, 공유 사진은 한 번만 올림, 폭별 파일은 `sharp`) → 로컬 확인 → **사용자 승인 뒤** 운영.
- [x] **T8 정리** — 운영 확인 뒤 `departments.ts` 의 값 · 부서 전용 사진(`standin-*` · `dep_manager*` · 고아 `DepartmentDetail` — `staff/*` 는 «섬기는 이들» 이 같이 써서 남김) · 옮기기 스크립트를 지우고 `images:variants` 를 다시 만든다.
