# 관리자 패키지 D(홈페이지 메뉴 + 예약 작업 + 정리) 구현 계획

> 사용자 결정: 짧은 계획 → 바로 구현. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 관리자 «메뉴 관리» 에서 홈페이지 메뉴의 이름 · 순서 · 사용 여부를 바꾸면 공개 사이트(헤더 · 휴대폰 메뉴 · 섹션 알약 · 페이지 제목)에 바로 반영되고, 끈 메뉴의 주소는 없는 페이지가 된다. 하루 한 번 예약 작업이 DB 정지를 막고 지난 것(휴지통 30일 · 새가족 1년 · 주인 없는 묶음 · 파일 8일)을 지운다.

**Architecture:** 어떤 페이지가 있는지는 지금처럼 코드(`siteNav`)가 정본이다. DB `menus(area = 'SITE')` 는 덮어쓸 값(이름 · 순서 · 사용 여부)만 갖고, 둘을 합치는 것은 순수 함수 하나(`mergeSiteNav`)다. 공개 쪽은 캐시한 합친 메뉴(`loadSiteNav`, 태그 `site-menus`)를 `(site)` 레이아웃이 한 번 읽어 클라이언트 부품(독 · 휴대폰 메뉴 · 섹션 머리)에 넘긴다. 끈 메뉴는 하위 페이지 폴더마다 둔 얇은 레이아웃(`siteMenuRoute`)이 404 로 끊고, 같은 곳에서 브라우저 제목을 만든다. 상위 주소(`/about`)는 빌드 때 정한 넘김 대신 켜진 첫 하위로 넘기는 페이지가 된다.

**Spec:** [2026-11-17-admin-design.md](2026-11-17-admin-design.md) — 6.5(메뉴) · 6.9(예약 작업) · 9(D). 앞 패키지는 [-pc-site-plan.md](2026-11-25-admin-pc-site-plan.md).

## Global Constraints

- 패키지 A~C 의 제약을 그대로 따른다(shadcn 규칙 · 글자 최소 · 공개 화면 장애 대비 · 공개 화면에 Supabase 클라이언트를 싣지 않음 · 로직 모듈은 테스트 먼저).
- **DB 를 읽지 못하면 코드의 기본 메뉴로 그린다** — 메뉴 때문에 사이트가 깨지지 않는다.
- 메뉴 켜기 · 끄기는 «전체 관리» 만(이미 `guard_menus`). 잠긴 메뉴는 끌 수 없다 — 이번에 DB 도 막는다.

## 내가 정한 값(계획에서 확인)

- **잠긴 홈페이지 메뉴**(홈 화면이 고정 링크로 가리키는 곳 — 코드에서 링크를 모두 찾아 정함): 찾아오시는 길 · 교회소식(홈의 «소식» 링크가 `/news`) · 교회소식 > 주일광고(`/news` 가 넘어갈 곳이 늘 하나는 있게) · 예배 · 예배 > 주일예배(홈 «지난 설교») · 다음세대 · 다음세대 8부서(홈 «다음세대» 카드). 교회소개 · 자료실과 그 하위는 끌 수 있다.
- **예약 작업 시각**: 매일 03:00(한국) = `0 18 * * *`(UTC). Vercel Hobby 는 하루 한 번 · 그 시간 안 어느 때.
- **예약 작업 비밀 값**: `CRON_SECRET`(Vercel 이 `Authorization: Bearer …` 로 붙여 부른다). 정본은 GitHub Secrets → «Sync env to Vercel».
- **Storage 파일 지우기**: 한 번에 1000개까지(`orphan_storage_objects(1000)`), 100개씩 나눠 지운다. 남으면 다음 날 이어서.
- **주인 없는 묶음 · 파일 기준**: 24시간 → 8일(쓰던 내용 임시 보관 7일 + 하루).

## 과제

- [x] **D1 DB** — `reference.sql` 에 홈페이지 메뉴(상위 6 · 하위 24, 잠김 포함)를 `siteNav` 와 같게 넣는다(어긋나면 테스트가 잡는다). `guard_menus` 가 잠긴 메뉴 끄기를 막는다. `purge_expired` · `orphan_storage_objects` 의 24시간 → 8일. pgTAP.
- [x] **D2 합치기(순수)** — `mergeSiteNav(siteNav, rows)`: 이름(비면 코드 이름) · 순서 · 꺼짐(하위가 다 꺼지면 상위도) — DB 에 없는 항목은 코드대로. `menuState(nav, path)`(켜짐 · 이름). 테스트 먼저.
- [x] **D3 읽기** — `loadSiteNav()`(공개 키 · `'use cache'` · 태그 `site-menus` · 못 읽으면 코드 기본값).
- [x] **D4 공개 화면** — `(site)` 레이아웃이 합친 메뉴를 넘기고(`SiteNavProvider`), 독 · 휴대폰 메뉴 · 섹션 머리 · 알약이 그것을 쓴다. 하위 폴더마다 `layout.tsx`(`siteMenuRoute` — 꺼졌으면 404, 제목 `«이름» | 성복교회`), 페이지의 같은 제목은 지운다. 상위 주소는 켜진 첫 하위로 307 을 주는 `route.ts`, `next.config` 의 섹션 넘김은 지운다(옛 주소 넘김은 남긴다).
- [x] **D5 관리자** — «메뉴 관리» 에 «관리자 · 홈페이지» 두 탭. 홈페이지 메뉴를 저장하면 공개 메뉴 태그를 갱신한다.
- [x] **D6 예약 작업** — `/api/cron/daily`(비밀 값 확인 → `purge_expired` → `orphan_storage_objects` → Storage 지우기, 결과를 로그에) · `vercel.json` 의 `crons` · `CRON_SECRET` 등록.
- [x] **D7 문서** — ADR(홈페이지 메뉴가 ADR 0004 의 «`siteNav` 단일 소스» 를 «코드 = 어떤 페이지, DB = 덮어쓸 값» 으로 바꿈) · `domains/admin.md` · 설계 9절 D 끝 표시.

시드 · `public/files` 는 패키지 B 에서 이미 지웠다(확인: 레포에 없음).

## 리뷰에서 더한 것(2026-11-25)

- 홈페이지 메뉴 이름 한도: 대메뉴 8자 · 하위 20자(DB check · 입력칸) — 위쪽 메뉴가 로고와 한 줄, 하위는 펼침 열 · 페이지 제목.
- 쓰던 내용 임시 보관의 7일을 «처음 보관한 때» 부터 센다(`writeDraft` 가 `savedAt` 을 이어받음) — 고칠 때마다 늘면 올린 지 8일 지난 파일이 지워진 뒤에도 «불러오기» 가 되어 깨진 그림이 저장됐다.
- 상위 주소 넘김은 메뉴를 못 읽으면 코드 메뉴로(경로 처리기에는 남길 직전 응답이 없다), 쿼리는 이어 준다.
- 공개 메뉴 캐시의 다시 읽기 60초 → 1시간(모든 공개 페이지가 레이아웃에서 읽는다 — 관리자 저장은 태그로 바로).
